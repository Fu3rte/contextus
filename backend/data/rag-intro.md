# RAG 是什么

RAG（Retrieval-Augmented Generation，检索增强生成）把「检索」和「生成」串起来：
先从知识库里找出与问题最相关的片段，再把这些片段塞进提示词，让大模型基于
真实资料作答。这样能缓解模型的幻觉，也能让回答带上可追溯的出处。

一个最基础的 RAG 只有三步：

1. 入库：把文档切分成小块，逐块调用 embedding 接口得到向量，写入向量库。
2. 检索：把用户问题也向量化，在向量库里按距离找出最相似的 top-k 个块。
3. 生成：把检索到的块拼成上下文，连同问题一起发给大模型，得到答案。

# 为什么要切分

embedding 模型有输入长度上限，而且过长的文本会把多个主题混进同一个向量，
导致检索精度下降。所以入库前要把长文档切成若干块，相邻块之间保留一段重叠
（overlap），避免正好在边界处切断一句完整的话。

# 相似度怎么算

向量检索通常用余弦距离。pgvector 里用 `<=>` 运算符表示余弦距离，距离越小
越相似；换算成相似度就是 1 减去距离。
